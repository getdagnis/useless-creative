# 0. HOW TO READ THIS DOCUMENT

This is a **state reconstruction**, not a claim that every idea below has already been implemented.

The project has evolved through several design and architecture passes. Therefore this document distinguishes:

- **Established direction** — repeatedly confirmed in the project context.
- **Current working concept** — the latest direction visible in sketches/data, even if not yet technically finalized.
- **Exploration** — ideas that were sketched or discussed but should not automatically become MVP requirements.
- **Open decision** — something that still needs a deliberate decision.
- **Deferred** — deliberately postponed until after validation/launch.

# 1. PROJECT IN ONE SENTENCE

**USELESS® is a concept-driven physical sticker brand using institutional/public-signage language and visually authoritative design to create absurd, cynical, existential, and increasingly AI-aware recontextualizations of everyday places and objects — launched through a participatory voting campaign.**

The physical sticker is the artifact.

The larger product is the **world / attitude / visual language** around the sticker.

---

# 2. CORE IDEA

USELESS® emerged from a simple cultural tension:

The world keeps attempting to make humans:

- faster
- smarter
- more efficient
- more productive
- more optimized
- more scalable
- more automated

USELESS® responds by deliberately occupying the opposite position.

The project embraces:

- uselessness
- inefficiency
- pauses
- mistakes
- absurdity
- unnecessary human behavior
- contradiction
- things that do not need to work
- being one update behind
- remaining human

The AI/automation layer is important because it gives the concept contemporary relevance, but the project is **not supposed to become generic AI merchandise**.

The broader USELESS world is about what happens when **official-looking systems are confronted with human irrationality and unnecessary meaning**.

---

# 3. THE CENTRAL CREATIVE PRINCIPLE

The most important creative rule developed during the mockup/usecase work is:

> **Do not merely place a sticker where its text makes literal sense. Place it where the environment makes the text acquire a new, unexpected meaning.**

In shorthand:

```text
literal fit = weak

semantic mismatch
+
recognizable object/place
+
unexpected interpretation
=
USELESS humor
```

Examples:

### Weak

`BEWARE OF SURPRISES` on a genuinely dangerous or surprising location.

That merely describes the place.

### Strong

`BEWARE OF SURPRISES` on:

- an empty waiting-room seat
- a train seat
- a boring public waiting hall
- a toilet stall
- an extremely predictable everyday situation

The humor comes from the fact that **there should be no surprise**.

---

Another example:

### Weak

`DO NOT TOUCH THIS. IT'S ALREADY TOUCHED` on a heavily handled button.

That reads literally.

### Strong

Put it on something that can be interpreted as **emotionally touched** or personally meaningful:

- a memorial plaque
- a framed photograph
- a sentimental object
- an abandoned personal item
- something carrying emotional residue

The joke becomes about the word "touched", not physical handling.

---

## 3.1 USECASE MEANS "MAKE THIS STICKER FUNNY HERE"

The `usecase` / `placement` metadata should therefore answer:

> "Where would this sticker create a surprising new interpretation of the object or place?"

It should **not** merely answer:

> "Where could this sticker physically be stuck?"

Both physical feasibility and semantic humor matter.

---

## 6.2 Sticker size

The working mockup assumption is approximately:

**16 × 4 cm**

This matters for image selection.

A stock image is useful only when:

1. the target surface is realistically large enough,
2. the sticker can occupy approximately 25–50% of the useful visible object area,
3. the object remains recognizable,
4. the final mockup still reads naturally enough to believe the sticker could exist there.

The goal is not to make the sticker microscopically realistic.

It should be large enough to be:

- readable
- visually dominant
- clearly attached to the object
- believable as a physical sticker.

# 9. SEEDING / EDITORIAL CONTROL

The project deliberately does not want pure popularity to erase the founder's curation.

Current idea:

- approximately 50–70 founder-selected stickers receive a **seed boost**
- this is represented by a high starting score / prior
- public voting then changes the ranking

This lets the founder communicate:

> "These are the ideas I believe belong in the USELESS universe."

without simply hard-coding the final winners.

# 10. CURRENT VOTING MODEL

The saved algorithm is more sophisticated than the UI needs to be.

The key concept is:

> Use a Bayesian ranking so early votes do not completely dominate and weak/new stickers still have opportunities.

---

## 10.1 Saved algorithm

Each sticker starts with:

```text
initial_score: 0..1000
```

Interpretation:

- editorial prior
- launch bias
- fallback quality estimate
- founder curation signal

Normalized:

```text
initial_prior = initial_score / 1000
```

---

## 10.2 Bayesian score

Saved model:

```text
bayesian_score =
  (v / (v + m)) * user_average
  +
  (m / (v + m)) * initial_prior
```

Where:

- `v` = number of votes
- `m` = prior weight / minimum vote threshold
- `user_average` = normalized user vote average

The saved baseline currently says:

```text
m = 50
```

This is **not yet implemented** and remains a tunable parameter.

A later discussion suggested testing lower values such as 20 so public signal can dominate sooner. That suggestion should not be treated as an adopted change.

---

## 10.3 Feed composition

Saved algorithm:

```text
60% highest bayesian_score
25% random from mid-tier
10% random from low-vote items
5% fully random
```

Purpose:

- top stickers receive enough exposure
- mid-tier stickers can climb
- low-vote items get opportunities
- fully random selection prevents total stagnation

This is a **ranking/feed strategy**, not a UI requirement.

---

## 10.4 Neglect boost

Saved algorithm:

```text
votes < 10
AND
age_days > 7
```

then:

```text
boosted_score = bayesian_score * 1.10
```

The boost is intended only for candidate selection.

It should not permanently mutate the sticker's base prior.

A later discussion suggested reducing the factor to 1.05. That was a suggestion, not a locked project decision.

---

## 10.5 ELO / battle mode

The saved algorithm contains an optional pairwise system:

```text
expected = 1 / (1 + 10 ^ ((opponent_rating - rating) / 400))

new_rating = old_rating + K * (result - expected)
```

with:

```text
K = 16..32
```

and possible combined scoring:

```text
final_score = 0.6 * bayesian_score + 0.4 * elo_score
```

However:

**1v1 battle mode is currently experimental and should not be allowed to complicate MVP unless deliberately chosen.**

The single-sticker judgement flow already provides enough data for first launch.

# 24. STOCK IMAGE SELECTION CRITERIA

For every candidate image, ask:

## A. Is the physical surface usable?

The sticker needs a reasonably flat or sufficiently regular surface.

Good:

- doors
- walls
- panels
- machines
- signs
- glass
- mirrors
- ticket machines
- card readers
- public transport panels

Potentially weak:

- highly curved objects
- complex textures
- tiny surfaces
- heavily occluded surfaces
- objects too far away
- visually chaotic environments

---

## B. Is the scale usable?

The sticker is approximately 16 × 4 cm.

The image must allow the sticker to occupy enough visual area to be readable.

Target:

```text
sticker = ~25–50% of useful object area
```

while still allowing the viewer to identify the object.

---

## C. Does the object remain recognizable?

Examples:

A door is still recognizable with:

- part of door
- handle
- surrounding frame

A wall is more useful if it has:

- cracks
- texture
- fixtures
- architectural clues

A completely blank wall is visually weak.

---

## D. Is there semantic surprise?

This is the main test.

Ask:

> Would this placement cause me to reinterpret the object?

If not, it is probably just a normal sign.

# 59. THE "UNEXPECTED MEANING" TEST

Every placement suggestion should pass this test:

### Question 1

Would the sticker make obvious literal sense here?

If yes, probably weak.

### Question 2

Does the location/object create a second meaning?

If yes, stronger.

### Question 3

Would a viewer understand the connection without explanation?

If no, probably too obscure.

### Question 4

Can a real stock photograph plausibly show the placement?

If no, discard.

### Question 5

Can the 16 × 4 cm sticker be large enough in the image?

If no, discard.

# 87. MASTER DECISION FRAMEWORK

## Question 1

Does it improve the first Kickstarter campaign?

If no → defer.

## Question 2

Does it materially improve:

- conversion
- participation
- product quality
- campaign clarity

If no → probably remove.

## Question 3

Does it add:

- new screens
- new product categories
- new moderation
- new database complexity
- new user systems

If yes → demand a very clear payoff.

## Question 4

Can the same outcome be achieved with:

- copy
- existing campaign comments
- one simple UI component
- manual curation

If yes → prefer the simple solution.
